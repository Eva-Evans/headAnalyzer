# EkoNiva Project 2

## Назначение
Приложение для расчёта прогноза структуры стада на заданный месяц по историческим событиям из БД или загруженных файлов.

Интерфейс реализован на Streamlit и состоит из трёх основных вкладок:
- прогноз по одному подразделению;
- просмотр/правка параметров модели;
- прогноз по хозяйствам (несколько подразделений).

## Технологии
- Python 3.11
- Streamlit
- pandas, numpy
- SQLAlchemy + psycopg2
- PostgreSQL
- openpyxl

## Быстрый запуск
### Через Docker
```bash
docker compose up --build
```
- UI: `http://localhost:8510`
- PostgreSQL: `localhost:15432`

### Локально
1. Создать и активировать venv.
2. Установить зависимости:
```bash
pip install -r requirements.txt
```
3. Запустить приложение:
```bash
streamlit run app.py
```

## Поток данных
1. Загрузка событий (xlsx/txt) через UI.
2. Парсинг и нормализация ETL-модулями (`etl/*`).
3. Запись в raw-таблицы PostgreSQL.
4. Расчёт параметров/переопределений.
5. Дневная симуляция до целевого месяца.
6. Показ таблиц в UI и выгрузка в Excel.

## Структура репозитория

### Точка входа и конфиг
- `app.py` — инициализация Streamlit, админ-режим, подключение вкладок.
- `config.py` — чтение `POSTGRES_DSN` из окружения.
- `db.py` — создание SQLAlchemy engine.

### UI
- `ui/tab1_forecast.py` — прогноз по одному подразделению, backtesting, Excel-выгрузка.
- `ui/tab2_params.py` — отображение параметров модели, админ-редактирование runtime overrides.
- `ui/tab3_farm.py` — мультихозяйственный режим:
  - загрузка пакетов файлов по подразделениям;
  - расчёт по выбранным хозяйствам;
  - кэш результатов;
  - рекомендации по переводам между подразделениями.
- `ui/tab3_data.py` — загрузка 3 базовых таблиц (legacy/служебный сценарий).
- `ui/styles.py` — форматирование таблиц и стили подсветки.

### Модель и расчёт
- `forecast_dynamic.py` — основной движок прогноза:
  - формирование стартового состояния стада;
  - дневная симуляция переходов состояний;
  - расчёт месячных показателей и переполнений.
- `forecast.py` — обёртка над динамическим расчётом:
  - вызов `compute_forecast_dynamic_from_db`;
  - дополнительные калибровки и fallback-расчёты.
- `sales_policy.py` — правила/структуры для расчёта реализации по вместимости.
- `params_runtime.py` — функции вычисления параметров из исторических данных (DIM, интервалы, выбытие и т.д.).

### Ядро (вспомогательные модули)
- `core/constants.py` — списки индикаторов и колонок переполнения.
- `core/helpers.py` — функции по датам, нормализации названий и доступу к значениям.
- `core/realization.py` — алгоритм ранней реализации по прогнозу переполнений.
- `core/excel_export.py` — сборка Excel-отчётов и подсветка значений.
- `core/params.py` — источник параметров, merge overrides, кэш параметров в БД.

### ETL
- `etl/calvings_births.py` — чтение/очистка файла отёлов и рождений.
- `etl/inseminations.py` — чтение/очистка файла осеменений.
- `etl/dryoff.py` — чтение/очистка файла запусков.
- `etl/disposals.py` — чтение/очистка файла выбытий.
- `etl/bulls.py` — чтение текстовой таблицы быков.

### Параметры модели и скрипты
- `model_params/defaults.py` — базовые константы и дефолтные параметры модели.
- `scripts/compute_model_params.py` — скрипт офлайн-расчёта параметров по данным БД.

### Инфраструктура
- `docker-compose.yml` — запуск `app` + `postgres`.
- `Dockerfile` — контейнер приложения.
- `db/init.sql` — инициализация схемы raw-таблиц.
- `requirements.txt` — зависимости Python.

## Как устроен прогноз внутри
- Состояние стада хранится в агрегированных массивах (`numpy`) по группам:
  - коровы по лактациям и DIM;
  - стельные коровы по дням до отёла;
  - тёлки и бычки по возрасту;
  - нетели по дням до отёла.
- На каждом дне симуляции выполняются переходы:
  - старение;
  - осеменение и доля успешных стельностей;
  - перевод в сухостой;
  - отёлы;
  - выбытие;
  - контроль вместимости на конце месяца.
- Переход в следующую лактацию происходит в момент отёла: из массива стельных текущей лактации животные переходят в массив open следующей лактации с `DIM=0`.

## Кэширование
- Для tab3 применяется кэш прогноза в БД (`tab3_forecast_cache`).
- Ключ кэша включает:
  - тип сущности (`farm`/`subdivision`),
  - имя сущности,
  - целевой месяц,
  - подпись данных,
  - хэш параметров.

## Текущее ограничение
В `core/params.py` функция `compute_params_from_db()` оставлена заглушкой (`NotImplementedError`).
Если нужен автоматический пересчёт параметров именно из `core/params.py`, её нужно реализовать.
